# Documento de Alcance

A continuación, se detallan las funcionalidades que se incorporarán al alcance del MVP para el sistema de control de acceso a instalaciones del Banco Andino. Este documento establece las características que se incorporarán al MVP, explicando cada una de ellas. También se incluyen las características que no se aplicarán al MVP, con su debida justificación y criterios para su posible implementación.

## Características icluidas dentro del MVP

1. **Gestión de empleados:** Funcionalidades para crear, obtener, actualizar, inhabilitar empleados. Estas funcionalidades se deben implementar porque es vital para el sistema ingresar y controlar la información de los empleados, ya que esta es en gran parte la información principal con la cual el sistema va a funcionar.

2. **Gestión de catálogo de tipo de documento:** Funcionalidades para crear, obtener, actualizar e inhabilitar tipos de documentos. Debido a que requiere información de empleados con documentos de identificación multipaís, utilizar tipos fijos de documentos puede generar problemas cada vez que se requiere un tipo de documento nuevo para un país, por lo que gestionar un catálogo de tipos de documentos es una mejor solución para este caso, aunque requiera algo más de trabajo inicial.

3. **Cargue masivo de empleados con archivo:** Funcionalidad de ingesta de datos de empleados para el sistema, de forma que se lean desde un archivo Excel, aplicando reglas de validación con severidad diferenciada y resultado de información validada (qué se registró, qué no y por qué). En la reunión se menciona que se deben ingresar los datos, al igual que saber qué registros ingresaron, cuáles no y por qué motivo. La reunión no aclara si este proceso se repite; probablemente es un proceso que se puede volver a llevar a cabo (ya que Yolanda menciona que el archivo se administra desde hace 3 años, es razonable pensar que seguirá enviando actualizaciones), así que diseñar este caso como una función reutilizable es mejor que solo pensar que es un proceso que se realiza una única vez.

4. **Integración con BioStar:** Integrar procesos en el sistema para sincronizar la información de los empleados hacia BioStar. Dentro de la reunión se indicó que este es un objetivo central, aunque no se puede acceder a un ambiente real, por lo que es importante poder simular este proceso.

5. **Gestión de eventos de ingreso y salida:** El sistema debe capturar/registrar eventos de ingreso y salida de personas por sede, y control de cierre de sesiones de acceso cuando no se registra salida, y de igual modo generar reportes y cálculos de ocupación. En la reunión se menciona que, aunque ya no es una obligación normativa, la gerencia se acostumbró a esa información y se pide que sea por medio de un tablero, al igual que se pide información de ingresos a las instalaciones, tanto por la Superintendencia como para el ministerio en Panamá.

6. **Exportación general:** Toda la información desplegada por el sistema debe poder exportarse (formato Excel mencionado explícitamente). Dentro de la reunión se menciona que se requiere exportar todo lo que el sistema muestre para poder descargarse, y que se debe manejar Excel, ya que se maneja todo con este tipo de archivo.

7. **Autenticación y roles de los usuarios del sistema propio:** Funcionalidades para autenticación, acceso al sistema y control de acceso por roles. Este tema no fue mencionado ni discutido dentro de la reunión, pero a partir de las funciones que se manejan en el sistema, la información que guarda y gestiona el sistema y cuáles actores van a realizarlas, es coherente asumir que se requiere un control de acceso al mismo.

## Características NO incluidas dentro del MVP

1. **Gestión de contratistas y visitantes:** Funciones para gestión de información para contratistas y visitantes. Dentro de la reunión se declaró explícitamente que por ahora solo se iniciaría con empleados, pero que muy probablemente se pedirá en el futuro. Con base en esto, en el alcance se tendrá en cuenta que se deben evitar decisiones que asuman la existencia de solo empleados. En cuanto a la posible implementación, esta se puede generar de una forma similar a la gestión de empleados, aunque se debe considerar qué información es requerida o no para cada tipo de persona registrada, y si es necesario incluir funciones de registro público para visitantes, por ejemplo (ya que estas se pueden manejar de forma diferente e incluir aspectos a evaluar en la implementación de la solución).

2. **Reporte dedicado para el ministerio de Panamá:** Exportar reporte personalizado de ingresos y salidas para ser entregado al ministerio de Panamá. En la reunion Alberto Sáenz menciono que necesita un reporte mensual para el ministerio de Panamá, no se menciona detalles especificos de como es el reporte o que información adicional debe incluir, por lo que no hay suficiente información para incluir esta funcionalidad dentro del alcance, por otro lado, Alberto también menciona que puede generar el mismo el reporte si tiene acceso a los datos, por lo que se podria suponer que con la generacion de reportes de salidas e ingresos que se inluiria en el alcance el puede usarlo como insumo para generar el reporte que necesaita para el ministerio de Panama. En cuanto a la posible implementación, depende de qué información adicional se requiere para generar el reporte y/o particularidades que debe llevar el mismo, aunque de forma funcional sería parecido a como se genera un reporte "normal", pero obviamente incluyendo las características necesarias que debe incluir el reporte.

3. **Aforo por piso/área:** Funcionalidades para gestionar información de pisos/áreas y gestión de eventos de entrada y salida por piso/área. El nivel de granularidad del aforo se discutió varias veces, ya que se pidió por piso, luego por espacio/área, y finalmente se acordó iniciar por sede, pero dejando la puerta abierta a mayor detalle después, sin definir cuándo ni cómo. Por otro lado, con base en la información proporcionada, no hay detalle específico de pisos y/o áreas/espacios, por lo que tampoco se podría usar esta información en la práctica por el momento. Teniendo en cuenta que se debe contemplar esta información aunque no se haya definido, se tendrá en cuenta esta misma en el desarrollo de la solución. En cuanto a la forma de implementar estas posibles funcionalidades, se podría manejar la gestión de creación, actualización, inhabilitación de esta información asociada con la sede, al igual que gestionar el ingreso y salida vinculado con la información de piso/área; se podría también incluso añadir a los reportes de forma opcional el detalle de piso/área.

4. **Gestión de informacion de sedes:** Funcionalidades para crear, actualizar informacion de sedes. Dentro de la reunion se mencionan 6 sedes, al igual que en el documento de Excel proporcionado se encuentran las 6 filas en los datos de las sedes, pero en los datos de empleados hay una sede no existente que no se menciono si existe o no, aunque se podria considerar necesario implementar la gestión de sedes, estos registros no crecen tanto como otros dentro del sistema y se pueden incluir registros adicionales dentro de la base de datos si es necesario, de igual forma incluir las funcionalidades supone extender algo mas el alcance del MVP y estas podrian incorporarse en un futuro si llega a ser necesario, por esto no se incluyo esta gestión en el alcance. En cuanto a la posible implementación, se podria manejar con funcionalidades para crear, actualizar e inhabilitar sedes.
